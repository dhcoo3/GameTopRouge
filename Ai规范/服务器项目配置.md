# 服务器项目配置

本文说明 Fantasy.Net 服务器监听配置、日志、本地启动参数和构建入口。服务器代码结构见[服务器代码规范](服务器代码规范.md)，共用协议和数据表生成流程见[通用项目配置](通用项目配置.md)。

## 项目与运行环境

- 服务器解决方案为 `Server/Server.sln`，项目目标框架在各 `.csproj` 中声明为 `.NET 10.0`。
- `Server/Main/Program.cs` 是服务入口，初始化程序集、配置 NLog 并启动 Fantasy.Net。
- `Server/Main/Properties/launchSettings.json` 面向本地开发；部署环境应单独提供参数，不应假设本地启动配置适用于生产环境。

- Fantasy.Net 服务配置位于 `Server/Entity/Fantasy.config`。调整场景、网络或框架运行参数后，应核对对应 Fantasy 组件和启动流程是否使用该配置。
- 登录认证使用 `LoginHttp` Scene 的 HTTP 20001 与 `Gate` Scene 的 KCP 20000。认证数据使用当前 World 数据库中的独立集合，说明及验收命令参见 `Server/README-Authentication.md`。
- NLog 配置位于 `Server/Main/NLog.config`，用于控制服务端日志目标和格式。修改日志策略时应保留足够的异常上下文，避免敏感信息进入普通日志。

## 监听端口

`Server/Entity/Fantasy.config` 当前配置如下。部署或跨设备联调时应检查防火墙、地址绑定及环境端口设置。

| Scene | 外网协议与端口 | 内网端口 |
| --- | --- | --- |
| `LoginHttp` | HTTP `20001` | `11003` |
| `Gate` | KCP `20000` | `11002` |

## 服务器数据表产物

运行 `Config/gen.bat` 后，服务器生成代码写入 `Server/Hotfix/Config/Code`，二进制数据写入 `Server/Hotfix/Config/Data`。共用数据表源和生成流程见[通用项目配置](通用项目配置.md)。

## 常用入口

| 任务 | 入口 |
| --- | --- |
| 编译服务器 | 在仓库根目录执行 `dotnet build Server/Server.sln` |
| 启动服务器 | 执行 `dotnet run --project Server/Main/Main.csproj` |
| 验证登录认证 | 参见 `Server/README-Authentication.md`；集成测试应使用独立数据库和随机端口 |
| 更新服务器数据表 | 运行 `Config/gen.bat`，确认 `Server/Hotfix/Config/Code` 和 `Server/Hotfix/Config/Data` 已更新 |
