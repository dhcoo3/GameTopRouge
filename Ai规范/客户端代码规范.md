# 客户端代码规范

本规范约定客户端目录职责、启动与玩法结构、UI 模块边界和 HTTP 请求方式。通用 C# 注释与质量要求见[通用代码规范](通用代码规范.md)，Unity 与运行配置见[客户端项目配置](客户端项目配置.md)。

## 客户端代码结构

主要业务代码位于 `Client/GameTopRouge/Assets/AAAGame`。

| 路径 | 职责 |
| --- | --- |
| `ScriptsBuiltin/Runtime` | 随客户端程序集发布的启动流程、资源更新、框架适配与基础组件 |
| `ScriptsHotfix` | 热更程序集中的玩法、UI、网络、实体和业务流程代码 |
| `ScriptsHotfix/Procedures` | 热更阶段的预加载、场景切换、主界面和游戏结束流程 |
| `ScriptsHotfix/GamePlay/Logic` | 游戏逻辑、帧同步、玩家、地图、单位、战斗、技能、子弹、伤害和 AI |
| `ScriptsHotfix/GamePlay/Render` | 将逻辑单位、地图、特效等表现到 Unity 场景中的渲染层 |
| `ScriptsHotfix/GamePlay/Logic/ProxyManager` | 游戏逻辑代理的注册、初始化、更新与回收 |
| `ScriptsHotfix/UI/Core` | UI 模块管理及 Model、View、Controller 的基础接口 |
| `ScriptsHotfix/UI/Module` | 主界面、战斗界面、关卡选择、登录和红点等 UI 业务模块 |
| `ScriptsHotfix/GameNetwork` | 客户端网络组件及协议辅助代码 |
| `ScriptsHotfix/Bridge` | 玩法逻辑与 UI 等层之间的交互入口 |
| `ScriptsHotfix/DataTable` | Luban 生成的数据表访问类 |
| `DataTable` | 客户端使用的二进制数据表资源 |
| `ScriptableAssets/Core` | 启动流程等客户端配置资产，例如流程列表 |
| `Scene`、`Prefabs`、`Sprites`、`Effect` | 场景、预制体、图片和特效资源 |

### 客户端启动与玩法流程

1. `LaunchProcedure` 初始化基础设置；根据资源模式进入热更 DLL 加载流程或资源更新流程。
2. `UpdateResourcesProcedure` 在可更新模式下检查版本、更新资源并校验资源；非更新模式直接初始化资源。
3. `LoadHotfixDllProcedure` 加载热更程序集，找到 `HotfixEntry.StartHotfixLogic` 并调用。
4. `HotfixEntry` 根据 `AppConfigs` 中的流程配置创建并启动流程状态机。
5. `PreloadProcedure` 初始化扩展组件和本地化数据；随后切换到 `Game` 场景及 `RunLoginProcedure`。
6. `RunLoginProcedure` 初始化 UI 模块并打开登录首页；游客按钮完成 HTTP 认证及 Gate 票据登录后才进入主线。
7. `GamePlayFacade.Run` 注册并初始化逻辑代理和渲染代理，进入指定玩法；`Update` 推进逻辑与渲染；`End` 清理代理和更新回调。

### 游戏逻辑与表现分层

- `GamePlay` 一级目录只包含 `Logic` 和 `Render`；按玩法域划分的逻辑代码放入 `Logic` 对应子目录，Unity 场景表现与交互脚本放入 `Render`。
- `GamePlay/Logic` 负责玩法状态和规则。核心代理继承 `GameProxy`，由 `GameProxyManger` 按顺序管理生命周期和逻辑更新。
- `GamePlay/Logic/Frame/FrameProxy` 以 30 Hz 推进联机逻辑，管理服务器帧、预测输入、历史状态和回滚重演。修改联机逻辑时，应避免依赖不确定的时间、随机数或容器遍历顺序；随机数应使用玩法提供的固定随机源。
- `GamePlay/Logic/Unit` 保存角色、子弹和范围效果等逻辑单位及其行为组件。
- `GamePlay/Render` 消费逻辑层数据并更新 Unity 实体、动画、地图、镜头和特效。玩法规则不应直接依赖具体 UI 或场景对象。
- UI 模块由 `UIModuleManager` 统一注册和打开；模块 Controller 负责协调界面行为，Model 保存模块状态，View 处理展示。

### Gameplay 与 UI 的依赖边界

- `GamePlay` 源码不得引用 `UI` 命名空间、UI 模块类型或 UI 单例；`UI` 模块不得直接引用 `GamePlay` 玩法类。跨层调用统一经过现有的 `Bridge/GamePlayToUIBridge`（Gameplay 请求展示、播放对话或更新 HUD）和 `Bridge/UIToGamePlayerBridge`（UI 请求启动玩法、读取或提交进度、占用玩家输入）。不得为同一边界另建适配器、通用事件总线或程序集。
- Bridge 负责把层内对象转换为稳定的只读数据载荷。Gameplay 的角色对象、进度服务对象和 UI Panel/View/Model 均不得穿过边界；已有单向事件机制可用于通知变化，但事件负载使用 Bridge 内定义的 DTO 或基础数据，不传递层内运行时对象。
- 面板、对话和地图交互需要暂停玩家输入时，通过 `UIToGamePlayerBridge.AcquirePlayerInputLock()` 获取独立 `IDisposable` 句柄，并由持有者在关闭、取消或异常路径释放。Gameplay 地图交互只查询 `InputProxy` 的输入锁状态，不轮询 UI 面板状态；禁止用一个共享布尔值由多个会话交替设置和清除。
- 项目当前保留单一 `Hotfix.asmdef`，依赖方向由上述入口和源码检查保证。新增跨层引用时，应先检查能否由对应 Bridge 的窄接口和 DTO 表达，再更新两侧调用及静态依赖扫描；不要为了强制边界拆分程序集。

## 客户端 UI 业务模块规范

项目采用自定义 MVC 式模块结构。按职责分离数据、业务编排和界面展示是合适的，但要限制跨模块直接调用，避免单例互相访问后形成强耦合。新增模块按需包含 `Model`、`Controller`、`View`、`Const` 和界面表单类；不需要某一层时不要为了目录整齐而创建空类。

| 部分 | 推荐职责 | 跨模块使用规则 |
| --- | --- | --- |
| `XxxModel` | 持有本模块状态，提供本模块数据的加载、查询与必要的共享只读接口；负责数据规则和状态变更 | 其它模块可通过窄接口读取稳定数据；状态写入由所属模块负责。避免将所有模块数据和任意业务方法集中到一个全局 Model |
| `XxxController` | 编排本模块用例，接收本模块 Panel 发起的 UI 输入，处理本模块协议和网络结果，校验数据并更新 Model | 默认只由模块内部调用。其它模块不要直接调用协议处理器；需要知道业务状态变化时，订阅本模块发布的语义事件 |
| `XxxView` | 可选的展示门面，提供共用提示、弹窗和打开本模块表单等界面能力 | 不承担协议收发、数据持久化或玩法规则。其他模块通过明确的 UI 入口提出展示请求，不直接操作目标模块的控件或表单实例 |
| `XxxConst` | 存放本模块固定常量、资源名、事件名等有明确含义的值 | 常量限定在所属模块；枚举使用独立、语义明确的枚举类型，避免把所有枚举和常量塞入一个无边界的 `Const` 类 |
| `XxxPanel` / `XxxForm` | 管理具体 Unity UI 表单的生命周期、控件绑定、按钮事件和界面状态展示 | 由本模块 View 或 UI 模块入口打开；按钮回调可直接调用本模块 Controller，业务规则由 Controller 或明确的业务服务处理 |

同一模块内，`XxxPanel` 负责控件绑定、按钮事件、界面状态显示和面板生命周期取消，可以在按钮回调中直接调用 `XxxController` 的公开用例入口，不必经 `XxxView` 转发。Controller 负责业务流程、协议调用及 Model 状态变更。需要把业务状态变化通知面板时，Controller 发布名称和负载都明确的语义事件，Panel 在打开期间订阅，并在关闭时解除订阅；若关闭会清理订阅，重新打开时应重新订阅。`XxxView` 是可选的展示门面，可提供共用展示能力或供模块外请求展示，不负责本模块按钮事件，也不作为协议调用中转站；不需要 View 时无需保留空类。

UI Prefab 是交付资源的一部分。新增或调整界面时，直接在 Unity 编辑器中制作并保存 Prefab 层级、布局和组件引用。不要为了生成一次或少量 Prefab，在 `Assets/Editor` 中新增 `QuestPrefabAuthoring` 这类临时 Editor 脚本或一次性资源生成器；交付后无人使用的生成代码会成为维护负担。只有确实纳入长期工作流的可复用编辑器工具，才按项目工具维护并说明用途。

### UI 文案与本地化

- 本地化文字统一直接调用 `GF.Localization.GetText(key)` 获取，不再新增模块 Text/Localize 方法、委托或属性作为转发接口。模块可以集中定义稳定的 key 常量；状态到 key 的映射可以保留，但只返回 key，由调用处使用统一接口获取译文。
- UI 业务代码不直接写面向玩家的中文；日志和调试输出不属于本地化范围。动态文字示例：`m_Title.text = GF.Localization.GetText("Quest.UI.Title");`。
- key 使用唯一、稳定、可读的模块前缀和语义名称，不使用中文译文、语言代码或临时序号。
- 本地化数据维护在 `Config/DataTables/Datas/#Localization.xlsx`，填写 key 及各语言译文，并按项目流程重新生成；不手改生成代码和二进制。缺失 key 的回显用于定位问题，不代替完整文案交付。
- Prefab 静态文字沿用既有本地化组件和刷新机制。运行时切换语言时刷新已显示控件，确保启动流程按当前语言加载数据。
- 业务层传递稳定错误码，由所属模块映射到本地化 key；不把中文提示作为业务判断依据。

### 协议处理与跨模块通知

Controller 可以接收和处理本模块协议，但处理顺序要清楚：校验协议结果、映射成模块需要的数据、更新 Model，再发布带有业务含义的事件。其它模块订阅事件后读取 Model 的最新状态，或使用事件负载中的必要数据；不要让多个模块各自订阅同一个底层协议并重复解释协议字段。

例如，背包 Controller 收到物品变化协议后更新背包 Model，并发布 `InventoryItemsChangedEvent`。任务模块需要刷新任务进度时监听该事件；它不直接调用背包 Controller，也不自行解析背包协议。事件应使用稳定、具体的名称和明确的数据类型，避免用难以辨认的数字 ID 或无类型 `object[]` 作为长期公共接口。订阅者应在生命周期结束时解除监听。

### 跨模块打开 UI

背包获得物品弹窗属于背包模块的展示能力。其它模块可以传入物品或奖励数据，请求背包模块展示；调用方不应自行拼装背包面板、访问其控件或依赖面板内部结构。

推荐公开清楚表达 UI 用途的入口，例如 `InventoryUI.ShowItemAcquiredAsync(rewards)` 或 `InventoryUIFacade.ShowItemAcquiredAsync(rewards)`，再由该入口委托给背包 View、UI 模块管理器和具体弹窗。数据参数使用明确的 DTO 或只读集合，并标注空值、生命周期和展示完成时机。若项目决定直接使用 `InventoryView.ShowItemAcquiredAsync(...)` 作为门面，也可以接受，但要确保 View 只负责展示，不混入协议或业务状态处理。

### 设计取舍

- **优点：** 按模块收拢数据、协议、事件和界面，方便定位代码；Controller 集中处理协议可以统一校验和更新状态；语义事件可以减少模块间直接依赖；通过模块 UI 入口复用弹窗，避免多个调用方重复实现展示流程。
- **风险：** Model 若同时成为所有模块的全局查询服务，容易膨胀成“上帝对象”；Controller 若同时负责网络底层、认证、重连、业务规则和 UI 导航，会变得过重；View 若承担跨模块调度、协议处理或业务决策，会模糊展示层边界；事件滥用会让调用关系变得隐蔽，难以追踪顺序和生命周期。
- **改进方式：** 保持模块内聚，模块外暴露少量读接口、语义事件和 UI 门面；复杂网络或业务能力再拆成 `XxxNetworkService`、`XxxService` 等有明确职责的类，由 Controller 编排。暂时无需引入完整 MVVM、依赖注入框架或额外中介者框架，先用稳定接口和类型化事件控制依赖方向。

推荐依赖方向：本模块 UI 输入进入 Controller，Controller 调用网络层并更新本模块 Model；Model 变化后由模块发布事件；其它模块监听事件或通过只读接口获取状态。跨模块展示请求进入目标模块 UI 门面，再由目标模块打开自己的表单。不要让模块互相直接调用彼此的 Controller 或访问彼此的界面控件。

## HTTP 与 HTTPS 请求

- 客户端业务层发送 HTTP/HTTPS 请求统一使用 Game Framework 的 `GF.WebRequest` 组件，并优先通过 `AddWebRequestAwait` 等可等待封装取得响应；业务代码不要自行创建或管理 `UnityWebRequest`。
- JSON 请求应使用 `GF.WebRequest` 的字节请求接口；项目 Unity 版本由该接口设置 JSON 内容类型。需要 Bearer 等请求头时，使用该组件支持的 `WWWForm` 请求并通过本次表单的 `headers` 设置请求头，不能写入全局默认头，也不能把令牌、密钥或完整认证请求体写入日志或 URL。
- 记录请求开始、耗时、响应字节数和传输错误。若当前 GF 版本的失败事件只提供错误文本而不公开响应体或数值状态码，按错误文本记录并在业务层处理；不要为了读取这些信息修改外部框架。
- 超时遵循 `GF.WebRequest.Timeout` 配置。取消令牌至少要停止当前业务流程的等待和后续处理；若 GF 组件不支持中止底层请求，迟到的完成事件不得继续触发已关闭面板或已结束用例的操作。
- `Assets/Plugins/UnityGameFramework` 及其它第三方框架、包和供应商代码视为外部依赖，不直接修改。需要扩展能力时在 `ScriptsHotfix`、`ScriptsBuiltin` 等项目代码中适配，或调整项目自有的 HTTP/API 契约。
- 仅资源框架适配层或需要专用下载处理器的资源加载代码可以直接使用 Unity 传输 API；认证和一般 JSON API 不应绕过 `GF.WebRequest`。

## Login 模块现状

- Login 模块负责游客凭据、HTTP 授权、Gate 票据协议和重连策略；`LoginModel` 保存认证状态，`LoginController` 编排流程。
- 游客按钮事件由 `LoginPanel` 处理并直接调用 `LoginController`；`LoginPanel` 订阅登录状态变化以更新按钮。`LoginView` 只负责展示提示等界面能力，不转发按钮输入或认证协议。
